# 着地予想ダッシュボード｜NaAクリニック 更新パイプライン

日次の売上着地予想ページ（Netlify サイト `naaclinic`、https://naaclinic.netlify.app）を、
手作業の出力ファイルではなく KOS OpenAPI のデータから作り直すプログラムです。

- ページのデータは `<script>` 先頭の1行定数（`const NAME = <JSON>;`）に入っています。`build.py` はこの行と
  `<span data-gen="…">` の文章だけを書き換え、CSS と描画コードには触れません（初回だけ下の「月の一般化」を適用）。
- 患者データ（API の生データ）は作業フォルダ `$WORK`（既定 `/tmp/sales-work/landing`、権限700）に置き、リポジトリには入れません。
- 売上目標は `pipeline/sales/targets.json`（`{"2026-10": 55000000}`）。月初に金額を追記します。
  `pipeline/.gitignore` が `*.json` を除外しているため、コミットするには `!sales/targets.json` の追記（または `git add -f`）が必要です。

## ファイル

| ファイル | 役割 |
|---|---|
| `fetch.py` | KOS 統計API（予約・決済・購入・施術・プリペイド）を月ごとに取得。決済は日ごとに取得して作成日を付ける。`--visitors` で生年月日（年代用）だけを取得・キャッシュ |
| `data.py` | 生データの読み込み・JST日付での索引・共通の判定（除外、初診/再診、予約金額、決済額、メニュー名） |
| `aggregate.py` | 日別レコード（`DAYS_*` の各要素）、当日の予想（`TODAY`）、目標の進捗（`TARGET`）、前月のグラフ（`MONTH`）・施術/プリペイド（`EXTRA`）、モデル係数 |
| `page.py` | 定数の読み書き、月の一般化（初回のみ）、生成文章の差し替え |
| `build.py` | 現行ページ＋APIデータ → 新しいページ |
| `verify.py` | 公開中の日を API から再計算して差分を表示（決済ベースの締め月合計が合わなければ exit 2） |
| `daily.py` | 0:00 の自動実行用：取得 → build → verify → ブラウザ表示チェック（公開はしない） |
| `check_render.js` | Chromium で全タブ・全日を表示し、エラー・NaN・undefined・Infinity があれば失敗 |
| `config.py` | 除外カテゴリ、来院率、HPB掲載メニュー、メモ判定の語など |

## 使い方

```bash
export WORK=/tmp/sales-work/landing            # リポジトリの外
python3 -I pipeline/sales/landing/daily.py     # 0:30 JST に実行。新しいページは $WORK/new.html
# 個別に
python3 -I pipeline/sales/landing/fetch.py --from 2026-10-01 --to 2026-10-12 --future-to 2026-10-31 --work $WORK --visitors 2026-10
python3 -I pipeline/sales/landing/build.py --html $WORK/current.html --work $WORK --out $WORK/new.html --today 2026-10-12
python3 -I pipeline/sales/landing/verify.py --html $WORK/current.html --work $WORK --all-fields
NODE_PATH=$(npm root -g) node pipeline/sales/landing/check_render.js $WORK/new.html
```

`daily.py` の終了コード: 0 = 公開できる状態、3 = その月の売上目標が `targets.json` にない（【要対応】として目標額を聞く）、
1 = 取得・作成・整合チェック・表示チェックのどれかが失敗。月の目標がないときは止める方針にした
（目標は当日パネル・目標の進捗・月末見込みの比較の3か所で使っており、目標なしで描く分岐はページにないため）。

## 毎日の処理（0:30 JST に実行。0:00 時点の予約で予想する）

1. 前日を締める：前日の日別レコードを API から作り、`DAYS_CUR` に追加（それより前の日は公開済みの値をそのまま残す）。
   - 予約時点（当日朝）の予想 `Amorning` = 前日0:00に公開した `TODAY.cur`（`AmSrc: "snapshot"`）
   - 当日キャンセル = 前日0:00の予約一覧 `TODAY.snap`（予約IDの先頭8文字。ページ自体に保存）にあって、いまキャンセル・ノーショーのもの
2. 当日の予想：いま入っている予約（0:00時点）から `TODAY` を作る。`TODAY.snap` に予約一覧を残す。
3. `TARGET`：実績 = 各日の決済ベースの売上（クリニック全体）、本日 = `TODAY.cur`、以降 = 前月の同じ曜日の平均。
4. 月の切り替え（1日の実行）：締めた月が `DAYS_BASE`（基準月）になり、`MONTH`・`EXTRA`・係数 `TODAY.coef` を API から作り直す。
   新しい月の日別タブは、1日分の実績ができるまで隠す。コードの変更は不要。
5. 月まとめ：「9月まとめ」（`SUMMARY`、手書き）はそのまま残す。月が締まると（翌月1日の実行で）「◯月まとめ」タブを `SUMMARIES` に足す（下の「月まとめ」）。

## 締めた日の修理（施術・購入データ）

`python3 -I pipeline/sales/landing/build.py --html PAGE --work $WORK --out NEW --repair-day 10/10 [9/27 ...]`
締めた日の、施術・購入・プリペイド由来の項目（売れた施術 `trTop`/`trCnt`/`trTot`、`kpi`、`swings`、`zeros`、
高単価施術 `push`、`prep`、増額・減額・決済0円の説明文）を API から作り直す。0:00 の予想・スナップショット由来の値と金額
（`Amorning`・`A`・`sameN`・差の内訳・`C`・`payC`）は変えない。

- ガード：施術タスクが10件以上あるのに施術実施額の合計が0、または価格のあるタスクが3割未満の日は、締めない・日中も公開しない（KOS に価格が反映されるのを待つ）。
- `verify.py --strict` は、売れた施術が10件以上あるのに金額0の日があれば FATAL。`daily.py` はその日を見つけると、作る前に自動で修理する。

## 日中の更新（12:25・14:25・16:25・18:25・20:25 JST）

`python3 -I pipeline/sales/daily_sales.py --intraday`（landing だけ。counselor は対象外）→ `landing/daily.py --intraday`。
公開中のページを取得し、当日分だけを取得して（`fetch.py --exact`、`$WORK/intraday`、約10秒）、次を更新する。

- `TODAY.live`（ページに元からある「現時点の決済」の欄。`TODAY.final` がなく `TODAY.live` があるときだけ表示）
  - 現時点の決済 = その日の決済ベースの売上（全体）、来院 = 完了した来院（スタッフ・PR枠除く）、客単価と来院ベースの決済（自費分を含む）
  - 残りの予約 = 予約状態が「予約」で開始がデータ時点以降のもの＋来院中で会計前のもの（当日に入った予約を含む）。時刻を過ぎた未来院は除く
  - 着地見込み = 現時点の決済 ＋ 残りの予約 ×（0:30の予想と同じ来院率・補完単価）。参考 = 予約金額に前月の上乗せ率
  - 売れた施術・2施術以上の割合・高単価施術・プリペイドの購入（その時点まで）
  - データ時点 = 取得した当日データの最新の時刻（決済・購入・施術・受付）。当日の実績がまだなければ実行時刻
- 来院済み／これから（0:00時点の予約が対象）、フッターの「◯時点のデータ」
- 当日の予想・`TODAY.snap`・係数・`DAYS_*`・`TARGET` は変えない（変わりそうなら止まる）。当日キャンセル（`sameN`）も変えない。
- その日の0:30の実行が公開されていなければ止まる。0:30 の通常実行は `TODAY.live` を空にして欄を消し、前日分を締める。
- KOS 統計は約20分ごと（毎時 :00・:20・:40 の1分後ごろ）にまとめて反映される（2026-10-12 深夜の実測：見えるまで5〜20分）。:25 に実行すると、その時刻の約15分前までが入る。
- テスト用：`daily.py --intraday --today 2026-10-12 --as-of 14:00 --html <その日のページ>` で、終わった日の14:00時点を再現できる（決済・購入・施術・プリペイドを14:00で切って取得。受付時刻が14:00より前の予約を来院とみなす）。

### API でできないこと・やり方を変えたこと

- **キャンセルの時刻が API にない。** 当日キャンセルは、毎日0:00の予約一覧（`TODAY.snap`）との差分で数える
  （以前の「日中の出力と閉院後の出力の突き合わせ」と同じ考え方で、0:00からの全キャンセルを拾うので件数は以前より多めになりうる）。
  0:00の記録がない日（過去の再現）は、予約状態「ノーショー」と予約メモ（「9/3山﨑 … キャンセル」の日付、「当日キャンセル」「来院なく」「無キャン」など）で判定し、
  前日・2日前以前・時期不明もメモから分ける。
- 当日予約は予約登録日時で判定できる（以前の「出力後に増えた予約」より正確）。
- 患者カテゴリ・流入経路は「いまの値」しか取れない。後からカテゴリが付いた・外れた患者は、過去の日の数字が公開時とずれる。

## 月まとめ（「◯月まとめ」タブ）

翌月1日の実行で、締めた月のまとめタブを1つ足します。以前のまとめタブ（「9月まとめ」を含む）はすべて残ります。

- **数値は build.py が作る**：上の5つの数字、決済ベースと来院ベースの表（プリペイドのチャージ件数も）、前2か月との比較
  （各月をAPIから同じ定義で計算）、曜日別、売れた施術、プリペイド（前2か月の件数も）、経路別・年代別（来院20件以上）、
  課題とOKRの「実績」列、OKRの見出しの売上目標（`targets.json` の翌月値。なければ「売上目標 未設定」）。
- **文章は日次ジョブの Claude が書く**：
  1. `daily.py` が `$WORK/summary_todo.json` を出して終了コード4で止まる（`numbers` = 表示する数値、`facts` = 文章用の事実、`text` = 空欄）。
  2. Claude が同じファイルの `text` を埋める。
  3. `daily.py --summary $WORK/summary_todo.json`（日次ジョブなら `daily_sales.py --only landing --summary …`）で作り直す。
     空欄が1つでも残っていれば、また終了コード4で止まる（未記入の項目名を表示）。

### 月まとめの文章（`text` の書き方の指針）

| 項目 | 書く場所 | 長さ |
|---|---|---|
| `cmpNote` | 「前2か月との比較」の表の下 | 1〜2文 |
| `weekNote` | 「曜日別」の下 | 1文 |
| `issues[0..4]` | 「◯月の課題」の5項目。`tag` は2〜4字の見出し（例：提案、減額、未入力、曜日、初診）、`text` は1〜2文 | 各60〜120字 |
| `okr.objective` | 翌月OKR（案）の Objective | 1文 |
| `okr.targets` | 翌月の目標（案）の列：`ratio`（実決済÷朝の予想）、`morning`（朝の予想の1日平均）、`multi`（2施術以上の割合）、`dn`（1日あたりの減額）、`course`（コース消化の来院での追加提案率）、`same`（当日キャンセル率） | 各「+15%以上」「154万円以上」程度 |
| `okr.note` | OKR表の下の注記（目標の組み立て方） | 1〜2文 |

- トーンと長さは「9月まとめ」に合わせる：です・ます調、短い断定、比較は「◯か月で最も高い」「前月より悪化」のように事実で書く。
- **数値は `numbers` と `facts` にある値だけを使う。** 推測や、ファイルにない数値は書かない（四捨五入した「約◯万円」は可）。
  例：曜日の売上と日割り目標の差は `facts` の「曜日別」を、前月からの変化は「前月からの変化」を使う。
- 課題は良くなかった指標（前月から悪化した、日割り目標を下回った曜日など）から5つ選び、原因の断定は避ける（「〜の可能性があります」）。
- OKR は「案」であることが見出しに出るので、本文で決定事項のように書かない。売上目標は `targets.json` の翌月値（`numbers.next.target`）で、
  未設定なら目標額に触れず、目標値の列も比率・件数で書く。`okr.note` では、目標額と朝の予想・上乗せ率の関係を `numbers` の値で示す。
- 患者名・カルテ番号・スタッフ個人名は書かない。

## 「この日の分析」（Slack 投稿用。ページには載せない）

0:30 の通常実行で前日を締めると、公開の準備ができたあとに `analysis.py` が `$WORK/daily_analysis.json` を出します
（`numbers` = 8項目の数値、`facts` = 数値をそのまま文にしたもの、`url`）。患者名・カルテ番号は入りません。
投稿は日次ジョブの Claude が Slack コネクタで行います（コードからは投稿しない）。分析が作れなくても公開は止めません。

| 項目 | 定義 |
|---|---|
| 1. 予想と実績の差 | 朝の予想（0:00時点）と着地結果（来院ベース・決済ベース）の差。寄与額＝当日予約の決済、当日キャンセル（予想に入っていた額：予約金額×来院率、未入力は平均単価）、増額、減額、決済0円、未入力の補完との差、スタッフ・PR枠の自費、プリペイド販売・プリペイドでの支払い・物販・取消返金（この4つは決済ベースだけの差）。高単価施術（HPB）の販売。目立ったケース＝予約金額との差が大きい来院2件（予約メニュー、実際の施術、予約になかった施術、その日のプリペイド購入）。年代と初診/再診だけで示す |
| 2. 当日キャンセル | 0:00 時点の予約一覧との差で確定した件数（0:00の記録がない日は予約状態とメモ。`判定方法` に書く） |
| 3. 2施術以上の割合 | 決済のあった来院のうち、施術の種類が2つ以上の割合。当月内の順位（高い順）、直近7日の平均、当月平均 |
