# 着地予想ダッシュボード｜NaAクリニック 更新パイプライン

日次の売上着地予想ページ（Netlify サイト `naaclinic`、https://naaclinic.netlify.app）を、
手作業の出力ファイルではなく KOS OpenAPI のデータから作り直すプログラムです。

- ページのデータは `<script>` 先頭の1行定数（`const NAME = <JSON>;`）に入っています。`build.py` はこの行と
  `<span data-gen="…">` の文章だけを書き換え、CSS と描画コードには触れません（初回だけ下の「月の一般化」を適用）。
- 患者データ（API の生データ）は作業フォルダ `$WORK`（既定 `/tmp/sales-work/landing`、権限700）に置き、リポジトリには入れません。
- 売上目標は `pipeline/sales/targets.json`（`{"2026-10": 55000000}`）。月初に金額を追記します。
  `pipeline/.gitignore` が `*.json` を除外しているため、コミットするには `!sales/targets.json` の追記（または `git add -f`）が必要です。

## ファイル

| ファイル | 役割 |
|---|---|
| `fetch.py` | KOS 統計API（予約・決済・購入・施術・プリペイド）を月ごとに取得。決済は日ごとに取得して作成日を付ける。`--visitors` で生年月日（年代用）だけを取得・キャッシュ |
| `data.py` | 生データの読み込み・JST日付での索引・共通の判定（除外、初診/再診、予約金額、決済額、メニュー名） |
| `aggregate.py` | 日別レコード（`DAYS_*` の各要素）、当日の予想（`TODAY`）、目標の進捗（`TARGET`）、前月のグラフ（`MONTH`）・施術/プリペイド（`EXTRA`）、モデル係数 |
| `page.py` | 定数の読み書き、月の一般化（初回のみ）、生成文章の差し替え |
| `build.py` | 現行ページ＋APIデータ → 新しいページ |
| `verify.py` | 公開中の日を API から再計算して差分を表示（決済ベースの締め月合計が合わなければ exit 2） |
| `daily.py` | 0:00 の自動実行用：取得 → build → verify → ブラウザ表示チェック（公開はしない） |
| `check_render.js` | Chromium で全タブ・全日を表示し、エラー・NaN・undefined・Infinity があれば失敗 |
| `config.py` | 除外カテゴリ、来院率、HPB掲載メニュー、メモ判定の語など |

## 使い方

```bash
export WORK=/tmp/sales-work/landing            # リポジトリの外
python3 -I pipeline/sales/landing/daily.py     # 0:00 JST に実行。新しいページは $WORK/new.html
# 個別に
python3 -I pipeline/sales/landing/fetch.py --from 2026-10-01 --to 2026-10-12 --future-to 2026-10-31 --work $WORK --visitors 2026-10
python3 -I pipeline/sales/landing/build.py --html $WORK/current.html --work $WORK --out $WORK/new.html --today 2026-10-12
python3 -I pipeline/sales/landing/verify.py --html $WORK/current.html --work $WORK --all-fields
NODE_PATH=$(npm root -g) node pipeline/sales/landing/check_render.js $WORK/new.html
```

`daily.py` の終了コード: 0 = 公開できる状態、3 = その月の売上目標が `targets.json` にない（【要対応】として目標額を聞く）、
1 = 取得・作成・整合チェック・表示チェックのどれかが失敗。月の目標がないときは止める方針にした
（目標は当日パネル・目標の進捗・月末見込みの比較の3か所で使っており、目標なしで描く分岐はページにないため）。

## 毎日の処理（0:00 JST）

1. 前日を締める：前日の日別レコードを API から作り、`DAYS_CUR` に追加（それより前の日は公開済みの値をそのまま残す）。
   - 予約時点（当日朝）の予想 `Amorning` = 前日0:00に公開した `TODAY.cur`（`AmSrc: "snapshot"`）
   - 当日キャンセル = 前日0:00の予約一覧 `TODAY.snap`（予約IDの先頭8文字。ページ自体に保存）にあって、いまキャンセル・ノーショーのもの
2. 当日の予想：いま入っている予約（0:00時点）から `TODAY` を作る。`TODAY.snap` に予約一覧を残す。
3. `TARGET`：実績 = 各日の決済ベースの売上（クリニック全体）、本日 = `TODAY.cur`、以降 = 前月の同じ曜日の平均。
4. 月の切り替え（1日の実行）：締めた月が `DAYS_BASE`（基準月）になり、`MONTH`・`EXTRA`・係数 `TODAY.coef` を API から作り直す。
   新しい月の日別タブは、1日分の実績ができるまで隠す。コードの変更は不要。
5. `SUMMARY`（「9月まとめ」：課題・OKRの文章を含む月次レビュー）は自動では作り直さない。

## 集計ルール（ページの説明文と、公開データとの突き合わせで確認したもの）

| 着地結果（来院ベース, `C`） | 来院者の施術決済総額の合計 | `optionItemTotalPriceV2`（9月30日中23日・10月9/10日で公開値と一致） |

### API でできないこと・やり方を変えたこと

- **キャンセルの時刻が API にない。** 当日キャンセルは、毎日0:00の予約一覧（`TODAY.snap`）との差分で数える
  （以前の「日中の出力と閉院後の出力の突き合わせ」と同じ考え方で、0:00からの全キャンセルを拾うので件数は以前より多めになりうる）。
  0:00の記録がない日（過去の再現）は、予約状態「ノーショー」と予約メモ（「9/3山﨑 … キャンセル」の日付、「当日キャンセル」「来院なく」「無キャン」など）で判定し、
  前日・2日前以前・時期不明もメモから分ける。
- 当日予約は予約登録日時で判定できる（以前の「出力後に増えた予約」より正確）。
- 患者カテゴリ・流入経路は「いまの値」しか取れない。後からカテゴリが付いた・外れた患者は、過去の日の数字が公開時とずれる。
