# 看護師ダッシュボード 更新パイプライン

Netlify `naa-nurse`（https://naa-nurse.netlify.app）の「NaA 看護師ダッシュボード」を、
Excel エクスポート（施術・購入・満足度調査）ではなく KOS OpenAPI から作り直す。Python 標準ライブラリだけで動く。

> **患者データはリポジトリに入れない。** API の生データ・生成した HTML は作業フォルダ（`/tmp/sales-work/nurse`、chmod 700）に置く。

## ページの仕組み

ページは `const EMBED = {T, P, S, files}` に **集計前の行**（Excel の3ファイルと同じ形）を持ち、集計・表示はページの JS
（`compute()` / `build()` / `render()`）がする。ページ内の「Excelを読み込む」で3ファイルを選んでも同じ JS で表示できる（この読み込みはそのまま残す）。
設定はページの JS の定数 `DOCTORS`（医師＝看護師の集計から外す）、`NON_STAFF`（非個人名）、`ALIAS`（逆順・短い名前の寄せ先）、
`MENTION`（「輝いていたスタッフ」の自由記述で数える短い呼び名）。`build.py` は EMBED の1行だけを差し替え、CSS / JS / 設定には触れない。

ページの「集計ルール」:
- 施術件数：施術データのグループ第1階層（施術者）が看護師のメニュー件数。商品のないカウンセリング行は除外。施術患者数は「日付×患者」のユニーク数。
- 医師施術の担当：施術者が医師で、メニューの担当者がその看護師だった件数（参考値）。
- 指名（確定）：購入データの施術外品目「看護師_○○」（指名料）の件数。返金済みは除外。
- 指名（推定）：患者分類に「看護師指名あり」があり、その日に指名料がない来院を、当日の施術者（いなければ担当者）の看護師に割り当て。
- 指名率：指名件数 ÷ 施術患者数。
- VOCガードレール：来院後アンケートの「施術の満足度（5段階）」。平均4.5以上かつ3以下なし＝良好／平均4.0〜4.5未満または3点あり＝注意／平均4.0未満または2点以下あり＝要確認。回答3件未満は「n少」。
- 輝きスタッフ言及：「本日特に輝いていたスタッフ」の自由記述で名前（姓・名）が挙がった回数（名前と `MENTION` の語の文字列一致。分類の判断は要らない）。

API との対応（`aggregate.py` 冒頭に詳細）: T＝施術タスク統計（完了日 JST、施術者＝doctorNames、商品名＝productTitle、担当者＝assigneeNames）、
P＝購入項目統計（施術外品目＝etceteraProduct*、患者分類＝visitorCategoryNames、会計状態）、S＝満足度調査の回答（提出日で期間を切る、日付は予約日時）。
患者キーは `P`＋md5(visitorId) 先頭8桁（Excel 版は患者名のハッシュ。ページでは同じ日の施術と購入を結ぶのにしか使わない）。

## ファイル

| ファイル | 役割 |
|---|---|
| `fetch.py` | 施術タスク・購入項目・満足度調査を月ごとに `WORK/raw/` へ（取得処理はカウンセラー版の `fetch.py` を使う） |
| `aggregate.py` | 生データ → EMBED（T・P・S の行） |
| `page.py` | EMBED と設定の読み書き、ページの JS の集計の Python 再現（`Calc`、`views()`） |
| `build.py` | 公開中の HTML ＋ API → 新しい HTML（EMBED だけ差し替え）。止まる条件・人の判断が要る名前の警告 |
| `verify.py` | ページの全表示（全期間・各日 × VOC 2種）の数値を API から作り直した値と突き合わせる（`--table`・`--raw`・`--strict`・`--expect`） |
| `check_render.js` | Chromium で全表示・並べ替え・行選択・散布図・Excel 欄を操作して JS エラー／NaN を検出。`--expect` で画面の数値を `verify.py` の値と照合 |

## 使い方

```bash
W=/tmp/sales-work/nurse; mkdir -p $W/out; chmod 700 $W
python3 -I -c "import sys; sys.path.insert(0,'pipeline'); import netlify; netlify.download('naa-nurse', '$W/current.html')"
python3 -I pipeline/sales/nurse/build.py --html $W/current.html --work $W --out $W/out/new.html --fetch   # 当月1日〜前日
python3 -I pipeline/sales/nurse/verify.py $W/out/new.html $W --strict --expect $W/out/expect.json
NODE_PATH=$(npm root -g) node pipeline/sales/nurse/check_render.js $W/out/new.html --expect $W/out/expect.json
# 公開版（Excel 版）との照合
python3 -I pipeline/sales/nurse/verify.py $W/current.html $W --table --raw
```

毎日の実行は `python3 -I pipeline/sales/daily_sales.py --only nurse`（ダウンロード → 当月を取得して前日まで作る → verify --strict →
描画チェック → `require_password=False` で公開。約45秒）。まだ `ENABLED` に入れていない。
**初回だけ** `--only nurse --accept-closed-month-changes`（Excel 版のページを API 版に置き換える。数字が少し変わる。API 版のページに付けると止まる）。

- 期間: `--until`（省略時は前日 JST）の月の1日〜`--until`。毎月1日の実行では前月まるごと、2日からは新しい月だけになる。
  期間に施術が1件も無いとき（月初が休診など）は前月の1日からにする（ページの JS は施術の無い期間を表示できず落ちるため。確認済み）。
  `--from` で任意の初日にできる。
- 確認済み: 新しい日（10/11）、月替わり（9/29 → 9/30 → 10/1 → 10/2）、1日だけの期間、施術の無い月初、Excel 版からの切り替え。
- 止まる条件: `--until` が今のページの最終日より前／今のページと重なる日のうち2日以上前の日で、施術件数の合計が max(2件,2%) 超・
  指名件数が2件超ずれる／今のページが Excel 版なのに `--accept-closed-month-changes` が無い（または API 版なのに有る）。
- 公開（Netlify deploy）はこのパイプラインではしない（`daily_sales.py` がする）。

## 人の判断が要るもの（build.py の WARNING。`--strict-new-staff` で止める）

Claude の判断（コメントの分類など）は日次では要らない。名前の設定だけは人が決めて、**ページの JS の定数を直して一度公開**する
（`build.py` は公開中のページを毎回ダウンロードして EMBED だけ替えるので、直した定数はそのまま残る）。

- 医師なのに `DOCTORS` に無い → その人が看護師として表示される。`DOCTORS` に足す。
  （2026-10 時点: 退職した医師 **渡辺一惠** が無い。10月は「全回答」で1件の評価が看護師として出る。9月を表示すると施術96件が看護師扱いになる）
- `data/staff_roles.csv` に無い名前（新しい人、または表記ゆれ）→ csv に足す／表記ゆれなら `ALIAS`。
  （2026-10 時点: **吉澤沙也加**（施術の評価の対象。`MENTION` にはいる）が csv に無い）
- csv で看護師でも医師でもない人が施術者 → `NON_STAFF` に足すか判断。
- 指名料「看護師_○○」が期間の看護師の誰にも当たらない → `ALIAS` に短い名前を足す（例 `'神田':'神田令'`）。
- 今のページにも `MENTION` にも無い看護師 → KOS の表示名が「名 姓」の逆順なら `ALIAS`、短い呼び名（姓だけ等）で言及されそうなら `MENTION` に足す
  （例: 阿部彩乃は 10月から施術しているが `MENTION` に無い。フルネームでの言及だけ数える）。

## 照合結果（2026-10-12、公開版 = 10/1〜10/10 の Excel 版、`verify.py --table --raw`）

ページで選べる22表示（全期間・10日分 × VOC 2種）の全項目を比べた。表示の Python 再現はページの JS と全表示で一致（`check_render.js --expect`）。

| 表示 | 施術件数 | 施術患者数 | 指名（確定／推定） | 指名率 | VOC平均(n) | 看護師別の差 |
|---|---|---|---|---|---|---|
| 全期間 | 556 | 426 → 427 | 29／14 → 31／14 | 10.1% → 10.5% | 4.81(125) | 安食実香・白木舞・山口真由・猪俣花織 |
| 10/1〜10/7, 10/9 | 一致 | 一致 | 一致 | 一致 | 一致 | 10/1 猪俣花織のカテゴリ名のみ |
| 10/8 | 71 | 55 → 56 | 6／2 | 14.5% → 14.3% | 4.80(15) | 安食実香 −1件、白木舞 +1件・+1人 |
| 10/10 | 55 | 43 | – → 2／0 | – → 4.7% | 4.85(13) | 山口真由・白木舞 確定 +1 |

行単位: 施術 1539行中 1536行一致、購入は 10/1〜10/9 の 1060行すべて一致、満足度調査 1802行すべて一致。残りの差はすべて説明できる:
1. **10/10 の購入データ**（131行）が公開版に入っていなかった（ページ上部に「購入データ：10/10未取込」と出ていた）。API 版で埋まり、10/10 の指名料 2件（山口真由・白木舞）が入る。
2. **10/8 の1件の施術者がエクスポート後に KOS で修正**（安食実香 → 白木舞、【追加】アクアピール）。施術件数の合計は同じで、看護師間で1件移る。
3. **商品カテゴリ名「Pick UP!」→「👑Pick UP!」**（10/1〜10/4 のエクスポート後に名前が変わった）。カテゴリ構成の表で猪俣花織の1件が列を移るだけ（もう1件は医師なしの行で集計外）。
4. 満足度調査の自由記述に英語で「None」と書いた回答が Excel では空欄になっていた。API 版も空欄として扱う（`aggregate.s_rows`）。
